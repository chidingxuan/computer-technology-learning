# MISSION：为什么学大模型应用开发

更新日期：2026-09-18
适用范围：`03_大模型应用开发` 第01～08课

## 一句话任务

把已有的分层 FastAPI 聊天后端，逐步升级成一个能查询指定资料、回答可追溯来源、只调用白名单工具，并带自动测试与固定评估问题的 RAG 智能助手。

## 为什么是这个任务

- 背景：计算机技术专硕，希望未来从事大模型相关工作。
- 目标方向：大模型应用工程、AI Agent、大模型平台或 AI Infra。
- 判断依据：SDK 样板代码可以被 AI 替代，不容易被替代的是边界判断——数据如何进入模型、输出如何约束和验证、上下文如何组织、检索结果是否可靠、工具权限如何控制、怎样测试一个非确定性系统。

## 用这条主线判断"该学什么"

- 每节课的产出都必须能接进上面那条主线，否则降到"只需了解"。
- 遇到优先级分歧时问一句：这个知识点会不会出现在那条主线上？
- 课程顺序固定为：一次可靠的模型调用 → 可复用的提示词与参数控制 → 可校验的结构化输出 → 多轮与流式 → Embedding 与检索 → 带来源的 RAG → 受控工具调用 → 综合项目。

## 明确的非目标

- 不从模型数学原理讲起（那是第 05 阶段的主题）。
- 前端只要求读懂结构、能改接口、能定位错误，不要求独立实现页面。
- 不追求框架大全，优先使用官方 SDK 的基础能力，先看清数据流再引入上层封装。

## 教学时必须守住的边界

- 密钥只放在本地 `.env` 或环境变量，仓库只提交 `.env.example`。
- 单元测试默认使用假客户端和固定数据，不联网、不消耗额度。
- 模型输出一律视为不可信外部输入，进入业务逻辑前必须校验。
- 检索不到依据时允许明确回答"不知道"，回答必须能追溯来源。
- 工具调用必须有白名单、参数校验、超时和权限边界。
- 每节课只创建当前所需文件，后续课程先留在规划里。
