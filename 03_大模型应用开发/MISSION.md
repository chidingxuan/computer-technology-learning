# MISSION：为什么学大模型应用开发

更新日期：2026-10-15
适用范围：`03_大模型应用开发` A篇第01～08课、B篇第09～14课；全程安排见[课程总纲](../课程总纲.md)。

## 一句话任务

先把已有FastAPI聊天后端升级为可追溯、受控、可测试的RAG助手，再独立实现小型Coding Agent：在授权练习仓库中读代码、改补丁、运行测试、根据失败继续修复，并具备权限、预算、进度恢复和固定任务评估。

## 为什么是这个任务

- 背景：计算机技术专硕，希望未来从事大模型相关工作。
- 目标方向：大模型应用工程、AI Agent、大模型平台或 AI Infra。
- 判断依据：重点是数据、上下文、权限、恢复与验证的工程判断，不是重复抄SDK样板代码；后续再借此理解模型训练与系统瓶颈。用户已明确同意这一递进，不据此推断岗位侧重或已有掌握。

## 用这条主线判断"该学什么"

- 每节课的产出都必须能接进上面那条主线，否则降到"只需了解"。
- 遇到优先级分歧时问一句：这个知识点会不会出现在那条主线上？
- A篇顺序：可靠调用 → 提示词 → 结构化输出 → 多轮/流式 → 检索 → RAG → 受控工具循环 → RAG综合项目。
- B篇在第08课之后：代码工具 → 补丁/测试 → 执行隔离 → 上下文 → 恢复 → Coding Agent评估。不把它挤进单节综合项目，也不等训练全部学完才做。

## 明确的非目标

- 不从模型数学原理讲起（那是第 05 阶段的主题）。
- 前端只要求读懂结构、能改接口、能定位错误，不要求独立实现页面。
- 不追求框架大全，优先使用官方 SDK 的基础能力，先看清数据流再引入上层封装。
- 不把完整Claude Code复刻、多Agent或泄露源码作为必要前置；不在当前应用课混入大规模多模态训练。

## 教学时必须守住的边界

- 密钥只放在本地 `.env` 或环境变量，仓库只提交 `.env.example`。
- 单元测试默认使用假客户端和固定数据，不联网、不消耗额度。
- 模型输出一律视为不可信外部输入，进入业务逻辑前必须校验。
- 检索不到依据时允许明确回答"不知道"，回答必须能追溯来源。
- 工具调用必须有白名单、参数校验、超时和权限边界。
- 任意代码执行须先通过隔离验收；进度与测试证据分开，Agent不得改外部验收测试来骗通过。
- 新模型下载、GPU租用和外部上传按需另获授权，不因路线更新自动扩张预算。
- 每节课只创建当前所需文件，后续课程先留在规划里。
