# 速查：多轮对话与流式响应

## 数据与时刻

T1读取history → T2组装messages → T3请求 → T4累积片段 → T5终止 → T6结果 → T7提交。
history仅含完整user/assistant轮次；messages含system、所选历史、当前user；buffer是临时正文。
最近n轮=2*n条消息；0轮=[]，不能用history[-0:]。按轮裁剪不保证token预算。

## 本地规范化事件

| 输入 | 输出状态 | 正文处理 |
|---|---|---|
| delta，text为str/None | 接收中 | 按序追加，None忽略，空格保留 |
| done | complete | 停止读取 |
| error | failed | 停止读取，保留片段 |
| 无终止信号就耗尽 | incomplete | 保留片段 |

kind/text是本课应用协议，不是SDK原始字段。

## 真实DeepSeek连接（第2.1、2.6、3.3节）

- 默认模型：deepseek-flash；extra_body={"thinking":{"type":"disabled"}}。
- 原始正文：先choice=chunk.choices[0]，再取choice.delta.content；不是累计全文。
- stop → 教师适配器发done → complete。
- length → 保留片段但不发done/error → 耗尽后incomplete。
- 明确失败结束或已捕获网络异常 → error → failed；不抹掉已有正文。
- 单次遍历；无正文或无choices不当完成；生成器提前退出时close，finally关闭上游。
- 每个真实开关默认False；开启后每次运行新发请求。HTML与自动检测不联网。
- 本课默认只共享第一课密钥，不继承旧模型名；密钥不要写进Notebook或HTML。
- openai 2.54.0、python-dotenv 1.2.2、httpx 0.28.1验证；不自动重试。

## 接口索引

- build_request_messages(rule, history, question, max_turns) → 消息列表快照。
- collect_stream(events) → {"status": str, "text": str}。
- commit_turn(history, question, result) → 新成功历史；仅complete且text.strip()非空提交。
- message.copy() → 新字典；只复制列表不能隔离内部字典。
- "".join(pieces) → 正文字符串。
- generator的yield → 每次产生一项；同一迭代器只消费一次。

## 排错与练习索引

| 现象 | 检查 |
|---|---|
| 只保留半轮 | 第1节轮次定义 |
| 改快照影响history | 第1.2节消息字典复制 |
| 正文只剩最后一段 | 第2.2节追加而非覆盖 |
| 断开仍为complete | 第2.3节终止信号 |
| 失败半句入库 | 第3节成功提交 |
| JSON片段解析失败 | 完成后再做上一课解析与校验 |
| API只显示空片段 | 思考已关闭？本次结束原因及后续content是什么？ |
| 无法导入deepseek_stream | 从课程/阶段/仓库目录启动，运行2.1准备单元 |
| 真实实验没运行 | 对应单元的RUN_REAL_*是否为True？前置练习是否通过？ |
| length停在半句 | 输出预算不足；仍标incomplete，不当成功保存 |
