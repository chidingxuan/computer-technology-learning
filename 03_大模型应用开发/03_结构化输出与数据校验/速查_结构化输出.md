# 速查：结构化输出与数据校验

配套讲义：`03_结构化输出与数据校验_重制版.ipynb`（当前唯一版本）

本页只保留结论与索引，不重复讲义的讲解过程。目标是三个月后只翻这一页就能直接上手写代码。

## 1. 时间线（压缩版）

```text
T1 定义契约 → T2 导出说明书 → T3 装进请求 → [模型] → T4 回答文本
→ T5 检查拒绝 → T6 解析 JSON → T7 校验字段 → T8 业务使用
```

T1～T3 在请求发出之前；T5～T7 在回答回来之后。两段可分开调试。

## 2. 五个调用的输入与输出

| 调用 | 来自 | 输入 | 返回 | 失败时抛出 |
|---|---|---|---|---|
| `json.loads(text)` | 标准库 json | 字符串 | dict / list / 标量 | `json.JSONDecodeError` |
| `json.load(fp)` | 标准库 json | 文件对象 | 同上 | `json.JSONDecodeError` |
| `json.dumps(data, ensure_ascii=False)` | 标准库 json | 任意对象 | str | `TypeError` |
| `Model.model_validate(data)` | pydantic | dict | 模型实例 | `ValidationError` |
| `instance.model_dump()` | pydantic | 无 | dict | — |
| `Model.model_json_schema()` | pydantic | 无 | dict（规则） | — |

要点：`loads` 收字符串，`load` 收文件对象；`validate` 是"检查并创建"，`dump` 是"导出已有对象"。

## 3. 必填、可空、默认值的四种组合

| 字段声明 | 省略字段 | 显式字符串 | 显式 null |
|---|---|---|---|
| `author: str` | 错误 | 接受 | 错误 |
| `author: str \| None` | 错误 | 接受 | 接受 |
| `author: str \| None = None` | 填入 None | 接受 | 接受 |
| `author: str = ""` | 填入空字符串 | 接受 | 错误 |

"必填"问的是键能否缺失；"可空"问的是值能否为 None。两件事互不决定。

## 4. 字段规则用哪个工具声明

| 想要的效果 | 写法 |
|---|---|
| 只能取给定值 | `Literal["paper", "ebook"]` |
| 数字上下限 | `Field(ge=1, le=5)` |
| 禁止未声明字段 | `model_config = ConfigDict(extra="forbid")` |
| 关闭自动类型转换 | `model_config = ConfigDict(strict=True)` |

## 5. 收到回答之后的判断顺序

```python
if refusal:                       # 1 明确拒绝，优先于正文
    return "refused"
if content is None or not content.strip():   # 2 先判 None，再调用 strip
    return "empty"
try:
    Model.model_validate(json.loads(content))  # 3 解析，4 校验
except json.JSONDecodeError:
    return "bad_json"
except ValidationError:
    return "bad_fields"
return "ok"
```

| 情况 | 返回值 | data |
|---|---|---|
| refusal 非空 | `"refused"` | None |
| 正文缺失或纯空白 | `"empty"` | None |
| 非法 JSON、截断、代码围栏 | `"invalid_json"`（作业用名）/ `"bad_json"`（讲义用名） | None |
| JSON 合法但字段不符 | `"invalid_data"`（作业用名）/ `"bad_fields"`（讲义用名） | None |
| 全部合格 | `"ok"` | 校验后的字段字典 |

状态字符串是应用自己约定的，不是 HTTP 状态码，也不是服务商原样返回的字段。

## 6. 排错索引

| 现象 | 先去查 |
|---|---|
| `AttributeError: 'NoneType' object has no attribute 'strip'` | 判断顺序写反了，`content is None` 要放在 `strip()` 之前 |
| `AttributeError: 'str' object has no attribute 'read'` | 用 `json.load` 处理了字符串，应改用 `json.loads` |
| `ValidationError` 里字段名对不上 | 拿错了对象：讲义示例是图书，课堂练习是观影，作业是工单 |
| `ValidationError` 报 field required | 该字段没有默认值，省略字段必然失败 |
| 只想看哪个字段、哪类错误 | `error.errors()` 的 `loc`（字段元组）与 `type`（错误类别） |
| Schema 有规则但模型输出仍不合规 | 本地 Schema 不会被自动发送，必须由客户端写进请求 |
| 字段都对但内容不是原文 | 结构校验无法证明事实，需要拿来源核对 |

## 7. 术语（后续课程必须沿用）

`status` / `data`、`ok` / `refused` / `empty` / `bad_json` / `bad_fields`、`content` / `refusal`、`model_validate` / `model_dump` / `model_json_schema`。

不要为同一个概念换名字：每引入一套新名词，都是在向学习者额外收费。
