模型提议，应用执行

上一课由程序固定先检索；现在模型可以说“请查这个工具”。但它只返回一条请求，真正执行函数的是你的应用。

先看这条时间线

程序给模型菜单 → 模型返回名称/参数/ID
→ 程序查许可、校验参数、执行函数
→ 保留原请求，按ID交回结果 → 模型继续或最终回答

先预测下一步由谁做，再点按钮。这里只回放固定流程，不联网。

同一个名称背后有三样东西

东西作用
tools说明给模型的菜单：名称、用途、参数Schema；没有Python函数本体。
registry注册表名称映射到真实Python函数，值是函数而不是执行结果。
allowed_names白名单本次允许执行哪些工具；注册过也可能未获准。

正常：已注册且获准的get_opening接受branch_id，查本地字典。变化：未知分馆返回found=False，仍是查询成功。错误：模型要求delete_branch，本课没有许可，不能运行。

请求参数不是字典

function.name = "get_opening"
function.arguments = '{"branch_id":"lib-east"}'  # JSON字符串
validate_arguments(...) → {"branch_id":"lib-east"}  # Python字典

validate_arguments是教师函数，参数不符合本课工具契约就报错。通过校验后，应用调用注册函数；不使用eval，不按模型给的名称去globals找对象。Schema不是权限。

安全沙箱是限制代码可访问资源的隔离环境；只读工具、白名单和JSON不等于完整沙箱。本课不开放写入、Shell或私人文件读取；工具结果也不是新系统指令。
