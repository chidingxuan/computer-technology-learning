第一步：先看真实收到的东西

打开Notebook第2.1节，把那一格的RUN_REAL_REQUEST改为True，再运行该格。它只发送一次短请求：让旅行助手复述“先去西湖，再去灵隐寺”。会产生API费用；不想请求时保持False。

2026-10-10的一次真实观察如下。你得到的文字和分段可能不同，不要拿完整句子或片段数做固定测试答案。

text=''       finish_reason=None
text='先去'   finish_reason=None
text='西湖'   finish_reason=None
…
最终正文：先去西湖，再去灵隐寺。
最终finish_reason：stop

text='先去'是这次新增的文字，不是目前的全部回答。第一项的空字符串没有新增正文，也不表示回答完成。None表示还没有结束原因。

真实片段是SDK返回的对象。在Notebook里先取得choice = chunk.choices[0]：choice.delta.content是新增正文，choice.finish_reason是结束原因。它们由服务端提供，不是你填进请求的字段。

第二步：把片段接起来，不要覆盖

临时正文（buffer）只是程序里存放已收文字的地方，可以用字符串，也可以先用列表保存各段：

pieces = ["先去", "西湖", "，再去灵隐寺。"]
text = "".join(pieces)
print(text)  # 先去西湖，再去灵隐寺。

"".join(pieces)把列表中的字符串按顺序连接，中间不加分隔符。若每次写text = 新片段，前面的文字就被覆盖了。

None跳过；空字符串不增加文字；空格保留。例如["Hello", " world"]应该拼成"Hello world"，不要逐段strip成"Helloworld"。

第三步：有文字，不等于正常完成

本课关闭思考模式，只处理纯文本正文。下面是把DeepSeek结束原因转换为本课状态的规则，不是所有模型接口的通用规则：

真实情况本课状态已有文字
finish_reason="stop"complete：确认正常完成保留
finish_reason="length"incomplete：长度限制截断保留半句
明确失败或SDK网络异常failed：明确失败保留片段
没有结束原因，流就耗尽incomplete：无法确认完成保留片段

真实验证把输出上限设为8个token时，收到“以下是一份杭州三日旅行行程，”和length。循环结束了，但回答没完成。text记录收到了什么，status记录这次是否正常完成。

第四步：换成固定事件，独立练习

为了不让你的测试反复花钱，也不被随机分段影响，教师提供的deepseek_events负责“翻译”真实对象。你写的收集函数只接收以下字典：

{"kind": "delta", "text": "先去"}  # 新增正文
{"kind": "done"}                   # 确认正常完成
{"kind": "error"}                  # 明确失败

kind/text/done/error都是本课自己定义的名称。真实stop转换为done；length不产生done，读完后得到incomplete；明确失败转换为error。你不需要在练习2里读取choices或调用API。
