## 第三阶段前置规划：Docker与部署

### 阶段定位

前两个阶段已经解决了“如何写出结构清晰、可以测试的Python Web后端”。第三阶段解决“如何把应用连同运行环境交付出去，并在另一台机器上稳定启动”。

阶段主线使用第02阶段完成的AI聊天后端，但不会从第一课就直接处理完整项目。前几课先用最小示例分别掌握容器、镜像、端口、Dockerfile和数据卷，再逐步迁移到聊天后端，最后完成一次完整部署。

### 阶段完成标准

完成本阶段后，学习者应能够：

1. 解释镜像、容器、Dockerfile、数据卷、容器网络和Compose的关系；
2. 为Python/FastAPI项目编写可复现的容器构建配置；
3. 在容器中正确安装依赖、启动Uvicorn并映射端口；
4. 让SQLite等运行数据在容器重建后继续保留；
5. 使用Docker Compose组织应用、配置、网络和存储；
6. 在Linux服务器上完成基础部署、日志查看、重启和故障定位；
7. 独立把第06课AI聊天后端容器化并完成验收。

### 已具备的前置知识

- Python模块、包、虚拟环境、依赖管理和环境变量；
- FastAPI、Pydantic、Uvicorn与HTTP接口；
- 分层项目结构和pytest自动化测试；
- SQLite连接、表结构和文件持久化；
- 基础Linux命令、Git和相对路径。

### 课程拆分与依赖顺序

#### 01 Docker与容器基础

从虚拟环境的局限出发，认识宿主机、Docker Engine、镜像、容器、镜像仓库和容器生命周期。练习拉取并运行现成镜像，掌握`docker run`、`ps`、`logs`、`stop`和`rm`，理解宿主机端口与容器端口。

#### 02 Dockerfile与镜像构建

学习构建上下文以及`FROM`、`WORKDIR`、`COPY`、`RUN`、`EXPOSE`和`CMD`。通过最小Python程序理解镜像层和构建缓存，学习使用`.dockerignore`排除虚拟环境、Git目录与缓存文件。

#### 03 FastAPI应用容器化

把一个小型FastAPI应用放入容器，连接`requirements.txt`、Uvicorn启动命令、`0.0.0.0`监听和端口映射。使用`/health`接口、容器日志和自动化请求验证应用，并练习定位导入失败、端口不可达和容器立即退出。

#### 04 数据卷与SQLite持久化

区分镜像内容、容器可写层和持久化数据。通过SQLite文件观察删除容器后数据为什么消失，再使用bind mount和named volume保存数据。讲清宿主机路径、容器路径、权限和数据库文件位置之间的关系。

#### 05 Docker Compose服务编排

学习用`compose.yaml`声明服务、端口、环境变量、数据卷和依赖关系。先编排单个应用服务，再加入辅助服务理解容器名称、默认网络和服务间通信；掌握`docker compose up`、`down`、`logs`和`exec`。

#### 06 Linux服务器部署基础

把已经容器化的应用迁移到Linux服务器，学习远程目录、环境变量、端口开放、后台运行、自动重启和日志排查。介绍反向代理、域名、HTTPS和镜像仓库在部署链路中的位置，但只要求完成适合当前阶段的基础操作。

#### 07 AI聊天后端部署项目

综合前六课，把第02阶段的AI聊天后端制作成镜像，使用Compose管理应用配置与SQLite数据卷，在目标环境启动并验证所有接口。项目验收覆盖镜像重建、数据持久化、健康检查、日志、重启恢复、敏感配置隔离和完整API回归测试。

### 阶段统一实践原则

- 所有课程继续采用“概念 → 最小示例 → 即学即练 → 自动检测 → 作业”的结构；
- Docker命令必须解释命令、子命令、选项、参数和执行结果；
- 不要求死记命令，重点训练通过`ps`、`logs`、`inspect`和HTTP请求逐层定位问题；
- 所有仓库内路径使用相对路径，避免设备相关绝对路径；
- 不把`.venv`、`.git`、缓存、真实密钥和运行数据库打入镜像；
- 示例优先使用体积较小且版本明确的官方基础镜像；
- 涉及Docker当前行为、安装方式和平台差异时，以官方文档和实际环境验证为准；
- 学习用配置与生产级方案要明确区分，不把“能运行”直接等同于“适合生产”。

### 创建第一课前的环境检查

正式生成第01课前，先完成以下只读或安全检查：

1. 当前设备是否已安装Docker Desktop或其他可用Docker Engine；
2. `docker version`能否同时显示客户端和服务端信息；
3. `docker run --rm hello-world`能否正常拉取并运行；
4. 当前设备架构是否为ARM64，以及所选镜像是否支持该架构；
5. Docker可用磁盘空间和网络下载是否正常；
6. 第02阶段的AI聊天后端仍保持`34 passed`，作为最终项目基线。

环境检查完成后，再创建`03_Docker与部署/01_Docker与容器基础/`及其Notebook、作业和测试文件。
