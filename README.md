## 第三阶段整体规划：大模型应用开发

### 阶段定位

前两个阶段已经完成Python工程基础和一个分层、可测试的FastAPI聊天后端。本阶段不从模型数学原理开始，而是先学习如何把大模型安全、稳定、可测试地接入真实应用。主线项目会逐步把现有聊天后端中的规则回复替换为真实模型能力，并最终加入知识检索和工具调用。

本阶段优先学习不容易被AI完全替代的工程判断：数据如何进入模型、输出如何约束和验证、上下文如何组织、检索结果是否可靠、工具权限如何控制，以及怎样测试一个非确定性系统。具体SDK样板代码可以由AI辅助生成，但这些边界仍需要开发者理解和验收。

本阶段分两篇：A篇01～08保留当前RAG与工具助手主线；B篇09～14单独实现小型Coding Agent及其Harness，即模型外的工具、控制循环、上下文、权限、恢复和验证系统。不必先训练模型才能做Agent，也不把RAG或向量数据库作为所有Agent的必需组件。

### 阶段完成标准

完成本阶段后，应能够：

1. 安全配置模型API，并把一次模型调用封装成可替换、可测试的模块；
2. 根据任务设计提示词，理解模型参数对质量、成本和稳定性的影响；
3. 使用结构化输出把自然语言结果转换成经过校验的程序数据；
4. 管理多轮对话上下文并实现流式响应；
5. 解释Embedding、相似度和向量检索的基本工作过程；
6. 完成文档切分、检索、上下文组装和带来源回答的RAG流程；
7. 让模型按明确契约调用受控工具，并处理参数错误和工具失败；
8. 独立完成一个具有自动测试、基础评估和安全边界的RAG智能助手。

B篇另行验收：在授权的练习仓库中读代码、修改补丁、运行测试、根据失败继续修复；具备步骤/费用限制、执行隔离、上下文与恢复机制，并用固定任务报告真实成功与失败。A篇通过不等于B篇已经完成。

### 课程目录与内容

#### 01 调用真实大模型API

区分聊天产品、模型、API和SDK；学习API密钥、环境变量、聊天模型接口与兼容API、响应文本提取和常见错误。用依赖注入和假客户端完成不联网、不消耗额度的自动测试；不同模型接口契约不能仅因SDK相同而混用。

#### 02 提示词与模型参数

学习system/developer/user等指令层次、清晰任务描述、上下文、约束和输出要求；通过对照实验理解模型选择、推理强度、输出长度及随机性相关设置。建立提示词版本和测试样例，不把“多写几句提示词”当作可靠性保证。

#### 03 结构化输出与数据校验

让模型返回程序可以稳定消费的数据，而不是依赖字符串切割。学习JSON Schema、Pydantic校验、必填字段、枚举、可空值、拒绝和解析失败，并实现一个结构化信息提取功能。

#### 04 多轮对话与流式响应

学习消息历史、上下文窗口、服务端保存与手动管理历史的区别；实现多轮上下文和逐步显示的流式文本。讨论历史过长、重复提交、客户端断开以及不能把流式片段当成完整回答等边界。

#### 05 Embedding与向量检索

从“文本如何用于相似度比较”出发学习Embedding、向量、维度、余弦相似度和Top-K检索。当前第05课使用明确标注的手工教学坐标，不宣称已运行真实语义编码；真实文字基线与模型编码的对照在第06课衔接，不再重复布置基础数学算法题。

#### 06 RAG知识库问答

把文档加载、切分、Embedding、检索、上下文组装和回答串成完整RAG流程。重点学习引用来源、无答案处理、切分粒度、召回质量和提示注入风险，并为检索与回答分别编写测试。

#### 07 工具调用与Agent基础

学习工具定义、参数契约、模型发起工具请求、应用执行工具以及把结果交回模型的完整循环。先单工具，再两步依赖任务，覆盖未知工具、失败、重复调用和停止条件；工具调用ID与结果配对，不让模型请求自动变成执行权限。只使用白名单安全工具，明确超时、重试、幂等与人工确认；用假模型/工具做离线测试。Agent是模型、工具和控制循环的组合，不是一个新模型。

#### 08 RAG智能助手项目

综合前七课，把现有FastAPI聊天后端升级为一个可查询指定资料、展示来源并调用有限工具的智能助手。项目包含分层结构、配置隔离、会话记录、RAG、工具调用、错误处理、单元测试、接口回归测试和固定评估问题。分别验证检索/回答/工具路径、无依据拒答和权限阻断，记录失败案例，不把一次成功演示当作可靠性证明。本课保持应用项目边界，Coding Agent不硬塞进本课。

#### B篇09～14 Coding Agent与Harness工程

依次实现代码读取/搜索、补丁与测试反馈、执行权限与隔离、上下文选择与预算、状态持久化与恢复、固定任务综合评估。第10课只运行可丢弃样例和固定命令；第11课完成隔离验收前，不允许自主执行任意生成代码。最终验收由Agent不可读写的外部评估器执行，禁止改测试骗通过。

详细课次、前置知识与验收方式见[课程总纲第4节](课程总纲.md#coding-agent)。先单Agent与简单命令行，不默认需要多Agent、复杂UI或整套框架；源码学习以官方公开资料和许可明确的项目为准。

### 阶段实践原则

- 优先使用官方SDK的基础能力，先理解数据流，再按需要引入上层框架；
- 密钥只保存在本地环境变量或`.env`，仓库只提交`.env.example`；
- 单元测试默认使用假客户端和固定数据，不访问网络、不消耗API额度；
- 真实API验证与离线自动测试分开记录，不能用一次成功请求代替完整测试；
- 模型输出属于不可信外部输入，进入业务逻辑前必须校验；
- RAG回答必须能追溯来源，检索不到依据时允许明确回答“不知道”；
- 工具调用必须有白名单、参数校验、超时和权限边界；
- 每节课只创建当前所需文件，后续课程先保留在README规划中，不提前生成空目录。

## 后续阶段的深化原则

第04阶段先建立数学、数据和训练循环基础；第05阶段再实现小型语言模型预训练，并以图文对齐进入多模态；第06阶段从监督微调扩展到偏好优化与强化学习，不把LoRA当全部后训练；第07阶段区分推理服务与训练基础设施，后者包含数据、显存、并行、通信与恢复。

以同一个Coding Agent和固定任务作迁移载体：固定模型比较Harness策略，再固定Harness比较模型或后训练效果，最后比较服务与资源成本。没有硬件的实验明确标为待实测，不擅自租GPU或下载大模型；具体阶段表与资源边界见[课程总纲](课程总纲.md)。
